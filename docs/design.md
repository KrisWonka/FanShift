# FanShift 设计说明

2026-11-14 第一版。

## 要做什么

一个独立的 Mac 风扇控制软件，接替原来的「TG Pro + Hammerspoon 里的 tgpro-hotkey」，用起来和原来一样：

- 一个全局快捷键（默认 ⌃⌥⌘8）在档位列表里循环：Silence / Performance / Turbo，也可以加 Full Blast、Cooldown。
- 每个温度档位是一条「温度 → 风扇转速」曲线，在图上拖点编辑。
- 菜单栏显示当前档位的字母，点一下也能切档；屏幕中央弹提示。
- 开机自启；现有配置直接搬过来。

不做的事：不支持 M5 以外的机型（代码里留了位置）、不做签名公证、不做每个风扇单独一条曲线。

## 三个部分

```
FanShift.app（普通权限，菜单栏）              fanshiftd（root，launchd 启动）
┌──────────────────────────────────┐        ┌──────────────────────────────┐
│ 快捷键 / 菜单栏 / 提示 / 设置窗口  │        │ 只做三件事：                  │
│ 每 2 秒：读温度 → FanController   │  XPC   │  · 接管并设目标转速（带租约）  │
│         算出指令                  │ ─────▶ │  · 交还系统                   │
│ 指令 = 交还系统 / 每个风扇的转速   │        │  · 报告自己的版本和风扇范围    │
└──────────────────────────────────┘        └──────────────┬───────────────┘
        读 SMC、读传感器不需要权限                          │ 写 SMC（需要 root）
                                                           ▼
                                                    风扇（F0md/F1md、F0Tg/F1Tg）
```

- `Sources/CSMC`：AppleSMC 的 C 封装。结构体布局必须和内核一致，所以用 C 写。
- `Sources/FanShiftCore`：纯逻辑和硬件读取。`FanController`（档位状态机 + 曲线）、`FanGovernor`（root 端的接管与交还）都不碰硬件，时间和读数由外面传入，可以单元测试。
- `Sources/fanshiftd`：root 后台程序。
- `Sources/FanShiftApp`：菜单栏 App。
- `Sources/fanshiftctl`：命令行诊断工具（`status` / `sensors` / `shadow` / `calib` / `helper`）。

## 为什么这样分

**算转速放在 App 里，root 程序只管写。** TG Pro 本身也是这个结构（App 算、helper 写）。好处是 root 程序很小，对外只有三个操作，转速会被限制在风扇自己报告的范围内，别的进程连上来最多只能让风扇变快变慢。代价是 App 不运行时没人控制风扇——这正好用租约兜住：

**租约。** App 每 2 秒发一次目标转速，每次续 10 秒租约。root 程序 10 秒没收到，就把风扇交还系统。所以 App 崩溃、卡死、被杀，风扇最多 10 秒后回到系统控制；实际上 XPC 连接一断就立刻交还。

**不要被系统降频。** 没有窗口的菜单栏 App 会被 App Nap 拖慢定时器，一慢租约就过期。App 启动时声明了一个不可降频的活动（不阻止电脑睡眠），定时器用 strict 模式。

## 这台机器上风扇怎么控制（M5 Pro，Mac17,9，实测）

| 键 | 含义 | 类型 |
|---|---|---|
| `FNum` | 风扇数量，= 2 | ui8 |
| `F{n}Ac` | 实际转速 | flt |
| `F{n}Tg` | 目标转速 | flt |
| `F{n}Mn` / `F{n}Mx` | 转速范围，2317 ~ 7826 | flt |
| `F{n}md` | 模式：0 交还系统，1 由软件接管，3 系统温控在管 | ui8 |

- M5 上模式键是小写 `md`，没有 `Ftst` 键；M1–M4 是大写 `Md`，而且接管前要先写 `Ftst` 解锁（没实现，`SMCFans.needsUnlock` 会认出来并拒绝）。
- 写这些键必须是 root，普通用户会被内核拒绝（kr = 0xe00002c1）。
- 写 `md = 1` 后目标转速自动变成最低转速；写 `Tg` 后风扇几秒内到位；写 `md = 0` 后交还系统，温度不高时系统会让风扇停转。每次写入约 0.2 毫秒。
- 调用成功要同时看内核返回值和应答里的 result 字节（0x82 固件拒绝，0x84 没有这个键）。

## 曲线怎么换算成转速

目标是和 TG Pro 手感一致，所以先实测了 TG Pro 的做法（`fanshiftctl shadow` / `calib`，和它并排记录）：

1. **阶梯，不是连线。** 温度超过某个点，就用那个点的百分比，直到超过下一个点。没超过任何点 = 没有规则 = 交还系统。
2. **换级时缓缓过渡。** 从当前转速到新一级的转速，用大约 10 秒匀速走完。
3. **百分比按风扇范围折算。** 0% = 最低转速 2317，100% = 最高转速 7826。
4. **参考温度 = 最热的 CPU 核心，减 2°C，再做平滑。** CPU 核心温度来自 SMC 的 `Tp**` 键（本机 23 个）。四次标定共 216 行 TG Pro 稳定在某一级的数据里，「最热核心 − 2°C、平滑系数 0.3」算出的级别 100% 吻合；不减的话只有约 90%，待机时会比 TG Pro 高一级（多转 1600 转左右）。

FanShift 默认照这四条来。另外保留了「连直线」的取值方式（设置里可选），同一条曲线下它给出的转速不低于阶梯方式。修正值也可以在设置里改，0 就是原始读数。

标定只覆盖到了 55% 这一级（约 60°C 以下）。更高的级别没有实测数据：从后台启动的压力程序在这台机器上只能把温度推到 56°C 左右。

其他档位类型：

- **Auto**：不接管，完全交给系统。
- **Full Blast**：全速；可以设 N 分钟后自动交还系统。
- **Cooldown**：全速，直到芯片各温度点的平均值降到目标以下，然后交还系统并提示。
- 曲线上的 **Stop 点**：这一段不接管。已经接管时，温度要比边界再低 2°C 才交还，避免来回切。

## 安全兜底

| 情况 | 处理 |
|---|---|
| App 退出 / 崩溃 / 卡死 | 连接断开立刻交还；最迟 10 秒租约到期交还 |
| root 程序崩溃 | launchd 重新拉起，启动时发现标记文件（`/var/run/…holding`）就先交还 |
| root 程序收到退出信号 | 先交还再退出 |
| 电脑睡眠 | 睡前交还；唤醒后重新接管（每次设转速前都会检查模式，不是 1 就重新写） |
| 读不到温度 | 曲线档位直接交还系统 |
| 最热核心原始读数 ≥ 95°C | 不管曲线怎么画，直接全速（不受修正值和平滑影响） |
| 目标转速超出范围 | root 程序按风扇自己报告的范围截断 |
| 别的软件（比如 TG Pro）接管着风扇 | 我们没接管过就不会去「交还」，不动别人的控制 |

## 状态和配置

- 配置：`~/Library/Application Support/FanShift/config.json`。第一次启动时如果没有，就从旧版的 `~/.hammerspoon/tgpro-hotkey-config.json` 搬过来（旧文件不动）。旧版的传感器编号 4（Highest CPU）对应「最热的 CPU 核心」，0（Any Sensor）对应「所有传感器里最热的」。
- 当前档位：`state.json`，重启后恢复。Full Blast 到点、Cooldown 完成后，档位没变但实际已交还系统，菜单栏字母显示 `A`。
- 开发时用环境变量：`FANSHIFT_HOME` 换配置目录；`FANSHIFT_DRYRUN=1` 只打印指令不碰风扇；`FANSHIFT_DEBUG=1` 时 `kill -USR1` 相当于按一次快捷键；`FANSHIFT_SNAPSHOT_DIR` 把设置窗口各页存成图片。
